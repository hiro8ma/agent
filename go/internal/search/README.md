# search

転置インデックスで候補を絞り、候補だけを BM25 で採点する全文検索のパッケージ
ベクトル検索（`Flat` / `IVF`）、RRF の融合（`Hybrid`）、交差エンコーダの再ランク（`CrossRerank`）、ColBERT 型の `MaxSim` も同じパッケージに置いている

## 主語を前の項目に頼る項目の取りこぼし

教材の例は「マイルール」の集合で、1番が「6日に1回はカレーを食べる」、2番が「ただし仏滅には食べない」、8番が「レトルトカレーを温めたお湯は飲む」になっている
2番は「カレー」を含まないまま、1番の条件になっている
項目を1つずつ別の文書として索引すると、「カレーに関するルールは」で2番が取れない
社内規程のような項目の集合を合成し、チャンクの作り方を変えて、主語を前の項目に頼る項目をどれだけ取れるかと、そのために返す項目の量を測った

### データ

`contextchunk_test.go` の `newRuleCorpus` が、種1の乱数と雛形から作る

- 12の話題（出張 / 経費 / 休暇 / 在宅勤務 / 会議室 / 来客 / 社用車 / 備品 / パスワード / 残業 / 名刺 / 郵便物）を1つずつ節にし、節の見出しを話題名にした
- 話題ごとに主項目の雛形を16個持つ。主項目は主題（出張の交通手段など）で始まり、話題名を含む
- 16個のうち10個には、「ただし」「この場合は」「この場合も」「上記に加えて」で始まる後続の項目を1〜3個付けた。後続の項目は話題名の bigram を1つも含まない
- 後続の項目は前から1つずつ確率0.7で残し、残さなかった項目より後ろは捨てる。節の中の主項目の並びと、主項目に入れる数字も乱数で決める
- 項目は303件（節あたり22〜30件）で、うち主語を前に頼る項目は111件（36.6%）
- 主語を前に頼る項目のうち86件は主項目の直後にあり、25件は別の後続の項目の後ろにある

生成した節の一部

```
出張の交通手段は原則として公共交通機関とする
ただし始発で間に合わない場合は前泊を認める
この場合は前泊の理由を申請書に書く
上記に加えて、タクシーは深夜の移動に限る
```

クエリはどちらも「〜に関するルールは」の形にした
話題のクエリは正解が20件を超え、節を丸ごと返す方式の precision が節を当てたかどうかだけで決まるので、正解の少ない主題のクエリも足した

| クエリ | 例 | 件数 | 正解 | 正解の平均件数（うち主語を前に頼る項目） |
| --- | --- | --- | --- | --- |
| 話題のクエリ | 出張に関するルールは | 12 | 節の全項目 | 25.2（9.2） |
| 主題のクエリ | 出張の交通手段に関するルールは | 86 | 主項目と、残した後続の項目 | 2.3（1.3） |

主題のクエリは、後続の項目を1つ以上残した群だけで作った

### チャンクの作り方

| 方式 | 索引する文字列 |
| --- | --- |
| a 項目だけ | 項目の文 |
| b 見出しを付ける | 節の見出し（話題名）、改行、項目の文。Contextual Retrieval の文脈を LLM で作らず、見出しで代えた簡易版 |
| c 直前の項目を連結する | 同じ節の直前の項目、改行、項目の文。節の先頭の項目は a と同じ |
| d 節を丸ごと返す | 見出しと節の全項目を1文書にして索引する。順位の高い節から全項目を返し、返した項目が k 件以上になったところで止める |
| 全文 | 検索せずに全項目を返す。全文をプロンプトに入れる場合にあたる |
| 上限 | 正解のうち主語を前に頼る項目、残りの正解、正解でない項目の順に k 件を返す。各列の上限になる |

上の例の「この場合は前泊の理由を申請書に書く」は、b では `出張\nこの場合は前泊の理由を申請書に書く`、c では `ただし始発で間に合わない場合は前泊を認める\nこの場合は前泊の理由を申請書に書く` として索引する

BM25 は既定の `NewAnalyzer`（日本語は文字の bigram、正規化と除去語なし）、k1=1.2、b=0.75 で、クエリの文をそのまま渡した
Ruri は `cl-nagoya/ruri-v3-310m` で、クエリに `検索クエリ: `、文書に `検索文書: ` を付け、コサイン類似度の全探索（`Flat`）で上位 k 件を取った。d は BM25 だけで測った

### 動かし方

```bash
go test -run 'RuleCorpus|DependentItems|ChunkTexts|PreviousChunk|RuleQueries' ./internal/search   # データとチャンクの単体テスト
go test -run TestContextChunkReport -v ./internal/search                                           # BM25 の表（1秒かからない）
TEI_LIVE=1 go test -run TestLiveContextChunkRuri -v -timeout 0 ./internal/search                   # Ruri の表（約2分20秒）
```

Ruri は手元の Docker で動かす TEI に繋ぎ、外部の API は呼ばない。起動の手順は `../embedding/tei/README.md` にある

### 実行環境

Apple M5 Pro（15コア）、Go 1.27.0
TEI は `ghcr.io/huggingface/text-embeddings-inference:cpu-arm64-1.9.4` を Docker（CPU 6個、メモリの上限11.65GiB）で動かした

### 読み方

- recall@k は正解のうち返した項目に入った割合、依存 recall@k は主語を前に頼る項目だけで数えた割合、precision は返した項目のうち正解の割合で、どれもクエリで平均した
- 話題のクエリは正解が平均25.2件あるので、k 件だけ返す方式の recall@5 と @10 は上限の行（0.200 / 0.400）を超えない。この表で比べるのは依存 recall と precision
- d と全文は k によらず節や全項目を返すので、返した項目数の列が量の代償になる
- 主題のクエリは正解が平均2.3件なので、k 件返す方式の precision@5 は上限でも0.458

### 分かったこと

**項目だけの索引では、主語を前に頼る項目はほとんど取れない**
BM25 a の依存 recall@20 は、話題のクエリで0.017、主題のクエリで0.105だった
後続の項目は話題名の bigram を持たないので、BM25 では話題名が当たらない
Ruri a は0.110と0.310で BM25 より拾うが、話題のクエリの上位10件には1件も入らなかった

**見出しを付けると後続の項目も当たるが、話題名を2回含む主項目の後ろに並ぶ**
BM25 b の話題のクエリの依存 recall は、@10で0.037、@20で0.338だった
b の主項目は見出しと本文で話題名を2回含み、後続の項目は見出しの1回だけなので、BM25 の TF の差で主項目が先に来る
在宅勤務 / 社用車 / パスワード / 郵便物の4話題では、上位16件が主項目16件で埋まり、後続の項目は17位から並んだ
Ruri b は依存 recall@10 が0.213、@20 が0.527で、BM25 b より上位に後続の項目を出した

**主題で聞くと、直前の項目を連結した c が後続の項目を上位5件に出す**
主題のクエリの依存 recall@5 は BM25 c が0.841、Ruri c が0.742で、a（0.035 / 0.023）と b（0.058 / 0.298）を大きく上回った
c の後続の項目は主項目の文を含むので、主題の語（「交通手段」など）で当たる
b は話題名しか足さないので、同じ節のほかの主題の後続の項目と区別できない。BM25 b が上位5件に入れた、主項目の直後の後続の項目は86件中5件だった
上位5件では BM25 c の recall（0.895）が Ruri c（0.769）を上回った

**c は後続の項目が2つ続くと、2つ目を取れない**
c で足すのは直前の1項目だけなので、「ただし」の次の「この場合は」には主項目の語が入らない
BM25 c は主題のクエリの上位20件で、主項目の直後の後続の項目を86件中86件取ったが、2つ目より後ろの25件は1件しか取れなかった

**節を丸ごと返す d は取りこぼさないが、主題のクエリでは返した項目の9割が正解でない**
d はどのクエリでも最上位の節が正解の節で、recall と依存 recall は1.000だった
返した項目は平均25.2〜25.6件で、主題のクエリの precision は0.090になり、正解だけを5件並べたときの上限0.458の5分の1だった
話題のクエリの precision が1.000なのは、このデータでは節と話題が一致するため
全項目を返すと、precision は話題のクエリで0.083、主題のクエリで0.008まで下がる

**BM25 は自然文のクエリの「ルール」で、関係の無い項目を拾う**
BM25 a の話題のクエリの precision@5 は0.883で、Ruri a は1.000だった
「ルール」の bigram「ール」が「メール」を含む短い項目（「パスワードの通知はメールで送らない」など）に当たり、話題名が2文字の出張 / 休暇 / 来客 / 備品 / 名刺で上位5件に入った
