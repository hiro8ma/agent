# pairwise

ペア比較（pairwise）の評価で審査員が付けた勝ち / 負け / 引き分けの数から、勝率の区間 / 50%と区別できるかの判定 / 符号検定の p 値 / 複数の比較の Holm の補正 / 50%と見分けるのに要る件数を出す部品

2つのモデルの出力を20件で比べて11勝9敗なら、勝率55%の区間は [0.34, 0.74] で、50%と区別できない
どこまで勝ったと言えるかを、件数と区間を添えて出すために作った

## 構成

| ファイル | 中身 |
| --- | --- |
| `pairwise.go` | `Counts.Interval`（Wilson の区間と判定）/ `SignTest` / `RequiredN` / `Holm` / `Analyze` |
| `load.go` | `Load`（比較の一覧を .json か .csv から読む） |

## 動かし方

```bash
go test ./internal/pairwise   # 1秒ほど
make pairwisecheck            # testdata の合成の6件の比較を読む（ネットワークは使わない）
go run ./cmd/pairwisecheck -name "model-a vs model-b" -wins 11 -losses 9 -ties 0
go run ./cmd/pairwisecheck -p 0.55,0.6 比較の一覧.json
```

ファイルは次のどちらかの形で渡す

```json
[{"name": "model-a vs model-b", "wins": 11, "losses": 9, "ties": 0}]
```

```csv
name,wins,losses,ties
model-a vs model-b,11,9,0
```

勝ち / 負けは name の前側のモデルから見た数
JSON の知らない項目 / CSV の見出しの違い / 負の数はエラーにする
フラグとファイルを両方渡すと、全部を1つの族として Holm の補正をかける

## 計算の決め方

- 勝率の区間は Wilson の95%区間
  - 正規近似の区間は全勝と全敗で幅が0になり、18勝2敗では上限が1.031と1を超える
- 引き分けの扱いは2通りを出し、結果の行に扱いを書く
  - 引き分けを除くときは、勝ち / (勝ち + 負け)
  - 引き分けを0.5勝に数えるときは、(勝ち + 0.5 × 引き分け) / 全件
  - 0.5勝の区間は結果を勝ちか負けの2値とみなして分散を出すので、引き分けの割合 × 0.25だけ分散を大きく見積もる
- 判定は区間が0.5をまたぐかで決める
  - 下限が0.5を超えれば「50%と区別できる（勝ち）」、上限が0.5を下回れば「50%と区別できる（負け）」、それ以外は「区別できない」
  - 件数が0のとき（引き分けだけを除いたときを含む）は、勝率0.5、区間 [0, 1]、区別できないにする
- 符号検定は、引き分けを除いた勝ち負けで、勝率0.5の正確な二項検定（両側）
  - p 値は少ない側の裾の確率の2倍で、1を超えたら1にする
  - 判定は区間で決め、p 値では変えない
  - 件数が少ないと、区間の判定と p 値が食い違う
    - 4勝0敗は区間の下限が0.510で区別できる（勝ち）になるが、p 値は0.125
    - 9勝2敗は区間の下限が0.523で、p 値は0.065
- Holm の補正は、同時に渡した全部の比較の p 値を1つの族として行う
  - p 値を小さい順に並べ、i 番目（1から数える）に (比較の数 − i + 1) をかけ、前の値より小さくせず、1で頭打ちにする
  - 区間と判定は補正しない
  - 複数の比較から勝ちを言うときは、補正後の p 値を見る
- 要る件数は、勝ち負けの付いた件数 n を正規近似で出す
  - n = (z(0.975) × 0.5 + z(0.8) × √(p(1 − p)))² / (p − 0.5)²
  - z は標準正規分布の分位点で、p は真の勝率
  - 真の勝率0.55 / 0.60 / 0.65 / 0.70で、783 / 194 / 85 / 47件
  - 0.5を挟んで対称に出る（0.45は0.55と同じ783件）
  - 近似なので、この件数での正確な符号検定の検出力は80%に届かない
    - 二項分布で数えると78.9% / 76.4% / 73.6% / 78.0%になる
  - 引き分けが割合 t で出るなら、集める件数は n / (1 − t)
    - t が0.3で真の勝率0.60なら、194 / 0.7で278件

## testdata

`comparisons.json` と `comparisons.csv` は同じ6件の合成の比較で、モデルの名前は架空

| 比較 | 勝ち / 負け / 引き分け | 確かめること |
| --- | --- | --- |
| model-a vs model-b | 11 / 9 / 0 | 勝率55%は20件では区別できない |
| model-a vs model-c | 15 / 5 / 0 | p 値は0.041だが、6件で Holm の補正をかけると0.166 |
| model-a vs model-d | 18 / 2 / 0 | Holm の補正後も p 値が0.0024で5%を下回る |
| model-b vs model-c | 10 / 6 / 8 | 引き分けの扱いで勝率と区間が変わる |
| model-b vs model-d | 4 / 0 / 0 | 区間では区別できるが、p 値は0.125 |
| model-c vs model-d | 3 / 17 / 0 | 区別できる（負け） |

## 作らないもの

- 審査員の判定そのもの（LLM の呼び出し、出力の順の入れ替え、両方の順での一致の確認）
- 引き分けを3値のまま扱う検定（Davidson のモデルなど）
- 多くのモデルを比べたときの Bradley–Terry などでの順位の推定
- 今の件数で見分けられる勝率の下限（要る件数の逆）
