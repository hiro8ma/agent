# crawl

先方への負荷を抑えるクローラーの部品と、取り直しの方針ごとの鮮度の計算

記事の一覧のページから記事を取り込むときに、次の3つを測るために作った

- 負荷を抑える規則（robots.txt、同じホストへ1本、直近の取得時間の k 倍を待つ）で、取り込みの速さがどれだけ落ちるか
- 同じ取り直しの回数で、一様 / 変化の頻度に比例 / 最適の配分のどれが鮮度を高くするか
- 記事が掲載を終える（404になる）とき、終えた記事を出し続ける時間が、確認の間隔でどう変わるか

## 構成

| ファイル | 中身 |
| --- | --- |
| `robots.go` | `ParseRobots` / `RobotsFromFetch`。RFC 9309 の robots.txt。User-agent のグループを大文字小文字を区別せずに選び、無ければ `*`。最も長く一致した規則が勝ち、同じ長さなら Allow。`*` と末尾の `$`。取得の状態は 4xx を全部許可、5xx と到達できない場合を全部禁止にする |
| `normalize.go` | `Normalizer`。重複の判定に使う正規形。scheme と host の小文字、既定のポート、`#` 以降、`.` と `..` の区間（RFC 3986 の 5.2.4）、計測用のパラメータ（`utm_*` などを引数で渡す）、残りのパラメータの並べ替え |
| `frontier.go` | `Frontier`。ホストごとの待ち行列。同じホストへは同時に1件、次は「前の取得が終わった時刻 + k × その取得の時間」から。ホストをまたいでは取ってよい時刻の早い順。深さ / ホストごとの件数 / パスの同じ区間の繰り返しで罠を止める |
| `crawler.go` | `Crawler`。時計（`Clock`）と `http.Client` を差し替えられる。初めてのホストは robots.txt を先に取り、リダイレクトは自分で辿らずに待ち行列へ戻す。`<a href>` を `golang.org/x/net/html` で抜き出す。件数 / 時間 / 待ち行列が空で止まる |
| `freshness.go` | 鮮度の式 `(1 − e^(−λI)) / (λI)`、一様 / 比例 / 最適（Cho と Garcia-Molina）の配分、ポアソン過程の変化を引く模擬 |
| `delist.go` | 記事が出ては掲載を終えるサイトを、一覧のページと記事ごとの存在の確認で追う模擬 |

テストのサイトは `httptest.Server` で作り、Host の見出しで複数のサイトに見せる
宛先の名前によらずそのサーバーにつなぐので、テストは外のネットワークに出ない

## 動かし方

```bash
go test ./internal/crawl   # 数秒
make crawlfresh            # 表 A〜C（約2秒、ネットワークは使わない）
```

## 分かったこと

- 待ちを取得の時間の k 倍にすると、取得の時間の分布によらず、接続している割合は `1/(1+k)` になる。1ホストの取り込みは k=10で11倍遅くなる
- 裾の長い応答では、遅い応答の後ほど長く待つ。対数正規では、最も長い待ちが58秒になった。全件の所要は中央値ではなく平均の取得時間で決まる
- 同じ予算では、どの予算でも 最適 > 一様 > 比例 だった。比例は予算が1ページあたり0.25回のとき0.239で、一様の0.531の半分を下回る。変化の速いページに回数を集めても、そのページは最新に追いつかない
- 最適が一様を上回る幅は0.023〜0.029だった。予算が小さいほど、変化の速いページを0回にする（0.25回のとき1,648ページ）
- 掲載を終えた記事を出し続ける時間は、存在の確認の間隔の半分よりわずかに長い。一覧を見る間隔は新しい記事の遅れと見落としだけを決め、終えた記事の時間は変えない
- 条件付きの取得で確認の費用が10分の1になるなら、同じ費用で確認の間隔を10分の1にでき、終えた記事を出す時間は12.1時間から1.2時間になる

## 確かめていないこと

- 実際のサイトの取得時間と、変化の頻度の分布。表の分布は仮定
- robots.txt の予約文字（`?` の後の `:` や `/` など）の %XX の比較。ASCII でない文字と %xx の大文字小文字だけをそろえる
- 記事の掲載期間が指数分布でない場合（決まった日数で終わるキャンペーンなど）。指数分布なら、確認の時刻と掲載を終える時刻が独立なので、出し続ける時間は間隔の半分前後になる
- 一覧から消えたことで掲載の終了を推定する方法。一覧の1ページ目から古い記事が押し出されるのと見分けられないので、存在は記事ごとに確かめた
