# dedup

取り込んだ文書の完全重複と準重複を見つける部品と、既読の除外に使うブルームフィルタ

次の2つを測るために作った

- 取り込んだ記事の重複（完全重複と準重複）をどう見つけるか
- 推薦の枠で利用者ごとの既読の記事を外すとき、ブルームフィルタの偽陽性率とメモリはどれだけか

## 構成

| ファイル | 中身 |
| --- | --- |
| `exact.go` | `Text`（HTML のタグを外し、script と style を捨て、空白をまとめる）、`Fingerprint`（その SHA-256）、`Exact`（URL を `crawl.Normalizer` で正規化して URL の重複を、本文のハッシュで完全重複を見つける） |
| `bloom.go` | `Bloom`。N ビット、k 個のハッシュ。k 個の位置は h1 + i × h2 を mix64 で混ぜ直して作る。`BloomParams`（要素数 m と目標の偽陽性率から N と k）、`FalsePositiveRate`（(1−e^(−km/N))^k） |
| `minhash.go` | `CharShingles`（文字の k-グラム、日本語はこちら）、`WordShingles`（単語の k-グラム）、`Jaccard`、`MinHasher`（K 個のハッシュの最小値の署名）、`EstimateJaccard` |
| `lsh.go` | `LSH{Bands, Rows}`。帯ごとに値の組から文書を引く表を作り、どれかの帯で一致した組を1回ずつ出す。Rows=1 は署名の次元ごとの転置インデックス |

## 動かし方

```bash
go test ./internal/dedup   # 数秒
make dedupbench            # 表 D〜H（約5秒、ネットワークは使わない）
```

## 測定結果

`make dedupbench` の要点。Apple M5 Pro、Go 1.27。全部の表は実装のノートと `make dedupbench` の出力にある

### ブルームフィルタ（表 D、表 E）

- 1要素あたり10ビット、最適の k=7で、偽陽性率は式0.00819に対し実測0.00826（1万件）と0.00815（100万件）。16ビット、k=11で0.00046
- k を最適の2倍にすると、10ビットで0.019と、最適の2.3倍になった
- 既読50件で偽陽性率0.1%のフィルタは96バイトで、ID をそのまま持つ400バイトの24%。1%なら64バイト（16%）
- 既読1,000件では、0.1%のフィルタが1,800バイト、ID が8,000バイト。100万人で1.68GiB と7.45GiB
- 候補100件のうち偽陽性で誤って外す件数は、1%で1.0件、0.1%で0.11件

### MinHash と LSH（表 F、表 G）

- 文字の5-グラムで、K を16 / 64 / 256にすると、誤差の標準偏差は理論の √(J(1−J)/K) と5%ほどの差で一致した（J=0.43で0.116 / 0.056 / 0.030、理論0.122 / 0.061 / 0.031）
- 1万件の文書（半分は残りの半分を置き換えた編集）で、帯を b=16、r=4にすると候補は1,766組（全部の組の0.0035%）で、J ≥ 0.5の組の93%を拾い、候補の98%が作った組だった
- 署名の次元ごとの転置インデックス（b=m、r=1）は、m=64で1,244万組（24.9%）、m=256で2,157万組（43.2%）を候補にした。関係の無い組の J は平均0.0032でも、1次元で一致する確率が m 回重なる

### 2回目からキャッシュに入れる（表 H）

- Zipf の要求に1回しか来ない対象を25%混ぜ、LRU の1万件で、ヒット率は0.407から0.460に上がり、キャッシュへの書き込みは119万回から48万回に減った
- 50%混ぜると、1,000件のキャッシュで0.135から0.178、書き込みは173万回から55万回

## 分かったこと

- 二重ハッシュ h1 + i × h2 をそのまま位置にすると、N が数百ビットの小さいフィルタで偽陽性率が式より高くなった（N=719、k=10、50件で1.44倍）。位置が N を法にほぼ等間隔に並び、別のキーと位置を共有しやすい。mix64 で混ぜ直すと1.02倍になった。利用者ごとの既読のフィルタはこの大きさなので、効く
- MinHash で最小でなく最大を取っても、推定の精度は変わらない。最大どうしが一致する確率も J に等しいため。最小であることは、2つの集合の和の署名が位置ごとの小さい方になる性質で確かめる
- 関係の無い文書どうしの一致は、同じ頻出の断片で起きる。組を増やしても、1つの署名の種での一致の割合のばらつきは減らない（種を10通り変えて0.0025〜0.0053、厳密な J の平均0.0055）

## 確かめていないこと

- 実際の記事の本文。文書は、かなを並べた架空の語から作った
- 表記の揺れ（全角と半角、NFKC など）をそろえる正規化。`Text` はタグと空白だけをまとめる
- 既読のフィルタを、読んだ記事が増えたときに作り直す運用。フィルタは消せないので、期間で区切って作り直す必要がある
- 2回目から入れるキャッシュで、フィルタを途中で空にする運用（交互に2つを使うなど）。表 H はフィルタを空にしない
