# lost_in_the_middle

LLM が複数の文書の中央にある情報を使いにくい現象（lost-in-the-middle、中央忘却）を、ローカルの LLM で小さく再現する実験
あわせて、検索器が返した候補の一覧を並べ替える対策が効くかを、実際に並べ替えたプロンプトで生成して測る
LLM に候補の一覧を渡す処理で、並び順が答えをどれだけ変えるかを自分の手で確かめるのが目的
有料の API は呼ばず、Apple Silicon の上で mlx-lm を使って生成する

## 確かめること

- 正解を含む文書を一覧のどこに置くかで、正答率がどれだけ変わるか（U字になるか）
- 質問を文書の前にも置くと、位置による差が縮むか
- 検索器が関連度順に返した一覧を、上位の文書が両端に来るように並べ替えると、正答率が上がるか
- 文書数 K を増やすと、正答率と位置による差がどう変わるか

## データ

- Liu et al. "Lost in the Middle: How Language Models Use Long Contexts"（2023）の公開データを使う
  - GitHub の nelson-liu/lost-in-the-middle の `qa_data/20_total_documents/nq-open-20_total_documents_gold_at_0.jsonl.gz`
  - 実行時に取得して `qa_data/` に置く（コミットしない）
- 1問は、NaturalQuestions-Open の質問、正解の文字列（1つ以上）、正解を含む文書1件、正解を含まない外れの文書19件からなる
  - 外れの文書は、検索器（Contriever）が質問に関連が高いと判定した順に並んでいる
  - 文書は Wikipedia の段落で、20件で約2,000語（Gemma 3 のトークナイザで約3,000トークン）
- 正解文書を位置 p に置いた K 件の一覧は、外れの文書の上位K-1件の p 番目に正解文書を差し込んで作る
  - この作り方の結果が、Liu らの10件のファイル（正解文書が位置5のもの）と2,655問すべてで一致することを確かめた
  - Liu らの10件のファイルの外れの文書は、20件のファイルの外れの文書の上位9件と2,655問すべてで一致した
- 2,655問から、seed 0で50問を無作為に選んだ
  - 生成の時間を40分以内に収めるため（同じ Mac で別の MLX の生成も動かした）

## プロンプトと判定

- Liu らの `qa.prompt` の英語の文面に1文を足し、モデルのチャットの雛形に user の発話として入れる
  - 指示文、文書の一覧、`Question: 質問`、`Answer:` の順に並ぶ
  - 足した1文は `Answer with a short phrase on a single line.` で、Liu らの指示文の直後に置く
  - 文書は `Document [i](Title: タイトル) 本文` の形で1行に1件ずつ並べる
- 文書の前後に質問を置く条件は、Liu らの `qa_with_query_aware_contextualization.prompt` と同じく、指示文の直後と文書の後の2か所に質問を置く
- 文書なしの条件は、Liu らの `closedbook_qa.prompt` の `Question: 質問` と `Answer:` の前に、同じ1文を置く
- 貪欲デコードで最大64トークンを生成し、改行が出たらそこで打ち切る
- 正答の判定は Liu らの評価と同じにする
  - 出力の最初の行だけを取り出す（文書を写しただけの出力を正解にしないための Liu らの扱い）
  - 小文字にし、句読点と冠詞 a / an / the を除き、空白を詰める
  - 同じ処理をした正解の文字列のいずれかが含まれていれば正解とする
  - 先頭の空行を飛ばしてから最初の行を取る点だけが Liu らと違う

### 1文を足した理由

Liu らの文面のままでは、Gemma 3 4B が答えの前に前置きの行を書き、最初の行で判定すると答えを読めなかった
たとえば `Here's a breakdown of when the internet became accessible to the public, based on the provided search results:` の1行を書いてから箇条書きに移る
文面を変える前（`prompts.py` の `ANSWER_FORMAT` を入れない版）に同じ50問で測った結果は次のとおり

| 条件 | 正答率 | 最初の行が「:」で終わる前置きだった出力 |
|---|---:|---:|
| 文書なし | 28.0% | 16件 |
| 正解文書だけ | 88.0% | 2件 |
| 20件、正解文書が位置1 | 34.0% | 31件 |
| 20件、正解文書が位置5 | 38.0% | 29件 |
| 20件、正解文書が位置10 | 38.0% | 29件 |

- 20件のときは50件中29件から31件が前置きで終わり、位置による差より前置きの有無が正答率を決めていた
- 前置きが多いと分かった時点で止めたので、位置15と20は測っていない
- 1文を足した後は、Gemma 3 4B の961件と Gemma 2 2B の350件のどの出力も、最初の行が前置きで終わらなかった
- 判定を「全文に正解の文字列が含まれるか」に緩める方法は採らなかった
  - 箇条書きで候補を並べた出力が、どれか1つ当たれば正解になるため

## 条件

### 正解文書の位置

- 20件の一覧の位置1, 5, 10, 15, 20に正解文書を置き、残りの位置には外れの文書を関連度順に並べる
- 質問を文書の後だけに置く場合と、文書の前後の両方に置く場合を測る
  - 前後の両方に置く場合は、生成の時間を抑えるため位置1, 10, 20だけを測る

### 並べ替え

- 検索器が20件を関連度順に返し、正解文書がその r 位にある状況を想定する
- 次の2つの並べ方で、同じ問と同じ r のプロンプトを両方生成して比べる
  - (a) 関連度順のまま並べる（正解文書は位置 r に来る）
  - (b) 奇数位を先頭から、偶数位を末尾から並べる（6件なら1, 3, 5, 6, 4, 2位の順）
- (b) では上位の文書ほど一覧の両端に、下位の文書ほど中央に来る
  - 20件では、1位は位置1、2位は位置20、3位は位置2、19位は位置10、20位は位置11に来る
- r は次の2つの分布で決める
  - 上位に偏る分布は、r 位の確率を1/r に比例させる（1位が27.8%、2位が13.9%、20位が1.4%）
  - 一様な分布は、どの順位も5%
- 50問に、分布の比率どおりの件数で r を割り当て、どの問にどの r を当てるかを seed で入れ替える
  - 上位に偏る分布では1位が14問、2位が7問、3位が5問、4位と5位が3問ずつ、6位から8位が2問ずつ、9位から20位が1問ずつ
  - 一様な分布では1位から10位が3問ずつ、11位から20位が2問ずつ
  - 件数の端数は最大剰余法で丸める

### 文書数 K

- K=5, 10, 20で、正解文書を先頭、中央、末尾に置く
- 中央は K=5で位置3、K=10で位置5、K=20で位置10（K=10とK=20は Liu らの公開ファイルにある位置）
- K=5とK=10の外れの文書は、20件の外れの文書の上位K-1件を使う
- 正解文書だけを渡す条件（K=1）と、文書を渡さない条件も測る

## 実行

```sh
cd python/lost_in_the_middle
uv sync
uv run python experiment.py --questions 50 > outputs/gemma-3-4b.md
uv run python experiment.py --model mlx-community/gemma-2-2b-it-4bit --questions 50 \
  --experiments baseline position > outputs/gemma-2-2b.md
uv run pytest
uv run ruff check . && uv run ruff format --check . && uv run mypy .
```

- モデルは Hugging Face のキャッシュから読む（無ければ取得する）
- 生成結果は `outputs/cache/` にプロンプトのハッシュをキーにして書き、2回目以降は生成を飛ばす
- `outputs/` と `qa_data/` は `.gitignore` に入れている
- テストはモデルとデータを取得せずに通る
- Gemma 2 2B は、生成の時間を40分に収めるため、文書なし、正解文書だけ、正解文書の位置の3つだけを測った

## 結果

### Gemma 3 4B

| 条件 | 正答率 |
|---|---:|
| 文書なし | 20.0% |
| 正解文書だけ（K=1） | 74.0% |

正解文書の位置（K=20）

| 質問の位置 | 位置1 | 位置5 | 位置10 | 位置15 | 位置20 |
|---|---:|---:|---:|---:|---:|
| 文書の後だけ | 48.0% | 56.0% | 50.0% | 54.0% | 44.0% |
| 文書の前後 | 46.0% | - | 44.0% | - | 42.0% |

- 文書の後だけの5か所で、すべて正解が15問、すべて不正解が14問、位置で正誤が変わったのが21問
- 文書の前後と後だけを同じ問で比べると、前後だけ正解と後だけ正解は位置1で4問と5問、位置10で4問と7問、位置20で5問と6問

文書数 K（質問は文書の後だけ）

| K | 先頭 | 中央 | 末尾 | 3か所の平均 | 中央の位置 |
|---:|---:|---:|---:|---:|---:|
| 5 | 48.0% | 56.0% | 54.0% | 52.7% | 3 |
| 10 | 46.0% | 58.0% | 58.0% | 54.0% | 5 |
| 20 | 48.0% | 50.0% | 44.0% | 47.3% | 10 |

並べ替え（K=20、質問は文書の後だけ）

| r の分布 | 問数 | (a) 関連度順 | (b) 両端に寄せる | b - a | b だけ正解 | a だけ正解 |
|---|---:|---:|---:|---:|---:|---:|
| 上位に偏る（1/r に比例） | 50 | 52.0% | 52.0% | +0.0 | 3 | 3 |
| 一様 | 50 | 46.0% | 50.0% | +4.0 | 8 | 6 |

r ごとの内訳（2つの分布をまとめる）

| r | 件数 | (a) の正解文書の位置 | (a) | (b) の正解文書の位置 | (b) |
|---|---:|---|---:|---|---:|
| 1 | 17 | 1 | 41.2% | 1 | 41.2% |
| 2〜5 | 30 | 2〜5 | 50.0% | 20, 2, 19, 3 | 56.7% |
| 6〜10 | 23 | 6〜10 | 30.4% | 18, 4, 17, 5, 16 | 34.8% |
| 11〜20 | 30 | 11〜20 | 66.7% | 6, 15, 7, 14, 8, 13, 9, 12, 10, 11 | 63.3% |

### Gemma 2 2B

| 条件 | 正答率 |
|---|---:|
| 文書なし | 30.0% |
| 正解文書だけ（K=1） | 84.0% |

正解文書の位置（K=20）

| 質問の位置 | 位置1 | 位置5 | 位置10 | 位置15 | 位置20 |
|---|---:|---:|---:|---:|---:|
| 文書の後だけ | 48.0% | 48.0% | 56.0% | 56.0% | 60.0% |

- 5か所で、すべて正解が17問、すべて不正解が16問、位置で正誤が変わったのが17問

### 読み方

- 50問なので1問が2ポイントにあたり、正答率が50%前後のとき95%の幅はおよそ±14ポイントある
- 位置どうしの10ポイント未満の差は、この問数では偶然と区別できない
- 並べ替えと質問の位置は同じ問を対にして生成したので、「b だけ正解」と「a だけ正解」の件数の差を見る
- r ごとの内訳は行ごとに入る問が違うので、行の間の差は問の難しさの差で、位置の効果ではない
  - 行の中で (a) と (b) を比べる
- 正解文書だけでも100%に届かないのは、判定が正解の文字列をそのまま含むことを求めるため（正解が `Dr. Jesse Bennett` の問に `Jesse Bennett performed the first C-section in 1794.` と答えると不正解）

## 分かったこと

- U字は出なかった
  - Gemma 3 4B は位置1から20で44%から56%、Gemma 2 2B は48%から60%で、どちらも50問の幅に収まる
  - 論文では gpt-3.5-turbo で U字になり、20件の中央に置いたときの正答率が文書なしの正答率を下回った
  - 今回はどの位置でも、文書なしの正答率（Gemma 3 4B で20%、Gemma 2 2B で30%）を18ポイント以上上回った
- 並び順は答えを変えたが、向きは一定でなかった
  - Gemma 3 4B では、位置を変えると正誤が変わる問が50問中21問あった
  - 外した位置は特定の位置に偏らず、合計すると位置ごとの正答率がほぼ同じになった
- 両端に寄せる並べ替えは効かなかった
  - 上位に偏る分布で52.0%と52.0%、一様な分布で46.0%と50.0%
  - 対にすると b だけ正解と a だけ正解が3問と3問、8問と6問で、ほぼ釣り合った
  - 中央が不利でないモデルでは、上位を両端に移しても取り戻すものがない
- 質問を文書の前後に置いても上がらなかった
  - 位置1, 10, 20で後だけより2ポイントから6ポイント低く、対にした件数もほぼ釣り合った
  - 論文でも、複数文書の QA では質問を前後に置く効果は小さかった
- 文書数 K を増やすと、3か所の平均は5件で52.7%、10件で54.0%、20件で47.3%だった
  - 20件で下がったが、差は50問の幅に収まる
- 並び順より大きく正答率を動かしたのは、出力の形式だった
  - Liu らの文面のままでは、20件のときの出力の約6割が前置きの行で終わり、最初の行で判定できなかった
  - 1文を足すと前置きは無くなった
  - 小さいモデルで並び順の効果を測るときは、先に出力の形式と判定が合っているかを確かめる必要がある

## 制約

- 問は50問、seed は1つだけで、位置どうしの差は±14ポイントの幅の中にある
- 文書は20件まで（Gemma 3 4B のトークナイザで約3,000トークン）しか試していない
  - Gemma 3 4B は128Kトークンの文脈を扱うモデルで、中央の不利がもっと長い入力で出るかは未確認
- 指示文に1文を足したので、Liu らと同じプロンプトではない
- 判定は Liu らと同じ部分文字列の一致で、言い換えや短くした答えは不正解になる
- Gemma 2 2B は、並べ替え、文書数 K、質問の位置を測っていない
