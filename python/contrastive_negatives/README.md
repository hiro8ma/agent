# contrastive_negatives

対照学習の損失 InfoNCE（正例のスコアを、負例と並べた softmax で当てる損失）で候補検索のモデルを訓練するとき、負例の選び方と補正で検索の結果がどう変わるかを測る小さな実験
EC の商品推薦の候補検索を模した合成データを使う
numpy と torch だけで動き、CPU で約6分かかる

## 確かめること

- バッチ内の負例だけで訓練すると、人気の商品を上位に出さなくなるか
- 一様に引いた負例と logQ 補正を足すと、それが戻るか
- 正例と同じ商品が負例に入った列（偽の負例）を除くと、検索が変わるか
- 負例の数を増やしたとき、相互情報量の下界 `log N - 損失` が頭打ちになるか

## データ

| 項目 | 値 |
|---|---|
| 商品数 | 20,000 |
| 特徴 | 64次元。200個のクラスタの中心に正規分布の雑音を足す。1クラスタに100商品 |
| 人気 | Zipf 分布（指数1.0）。順位はクラスタと無関係に割り当てる |
| 正例対 | 基準の商品を人気に比例して引き、次に見た商品を同じクラスタから人気に比例して引く。基準の商品自身は除く |
| 件数 | 訓練300,000対、テスト20,000対。同じ分布から別に引く |
| 人気上位1% | 訓練で次に見た商品として出た回数の上位200商品 |

- 人気は特徴に含まれない
- 基準の商品と次に見た商品の相互情報量は、データを作った分布から厳密に計算でき、4.957 nats になる
- テストの正例の36.7%が人気上位1%の商品
- 訓練で一度も正例にならない商品が1,096ある

## モデルと損失

- 基準の商品の塔と候補の商品の塔を、それぞれ MLP（`64 -> 256 -> 32`）にし、出力を L2 正規化する
- 候補の商品の塔には商品 ID の埋め込みを足し、0で初期化する
  - 人気は特徴に含まれないので、人気を表すには商品ごとの埋め込みが要る
- ロジットは内積を温度0.05で割ったもの
- Adam（学習率0.003）で、バッチ1,024、8エポック訓練する

| 変種 | 負例の候補 | ロジットの扱い |
|---|---|---|
| a | バッチ内のほかの行の正例 | 内積 / 温度 |
| b | a に加え、一様に引いた商品をバッチと同じ件数（全行で共有） | 内積 / 温度 |
| c | b と同じ | 内積 / 温度 - log Q(商品) |
| d | b と同じ | c に加え、その行の正例と同じ商品の列を -inf にする。対角は残す |

- Q は商品が候補の列に出る確率
  - バッチ内の分は訓練の正例の出現頻度、一様な分は1/20,000とし、件数の比（バッチと同数なので1対1）で混ぜる

## 結果

### バッチ内で正例が重なる行

訓練データを並べ替えてバッチに切り、全バッチの平均を取った

| バッチサイズ | 正例が重なる行数 | 割合 | 一様な負例に正例が入る行数 |
|---:|---:|---:|---:|
| 256 | 54.7 | 0.214 | 3.3 |
| 1,024 | 402.6 | 0.393 | 50.1 |
| 4,096 | 2,455.8 | 0.600 | 760.9 |

- 正例が重なる行は、同じ商品をほかの行も正例に持つ行
- 一様な負例はバッチと同じ件数を引いた

### 検索の精度

バッチ1,024で、種3つの平均と標準偏差

| 変種 | recall@10 | recall@50 | 上位10件に占める人気上位1%の割合 |
|---|---:|---:|---:|
| a. バッチ内負例だけ | 0.163 ± 0.004 | 0.671 ± 0.011 | 0.038 ± 0.014 |
| b. a + 一様な負例 | 0.434 ± 0.006 | 0.839 ± 0.003 | 0.159 ± 0.014 |
| c. b + logQ 補正 | 0.593 ± 0.003 | 0.855 ± 0.000 | 0.276 ± 0.002 |
| d. c + 偽の負例の除外 | 0.594 ± 0.002 | 0.854 ± 0.000 | 0.276 ± 0.002 |
| 参考 人気順 | 0.104 | 0.210 | 1.000 |
| 参考 真の条件付き分布 | 0.634 | 0.885 | 0.279 |

- テストの基準の商品ごとに全商品を全探索し、基準の商品自身は候補から外す
- 「参考 真の条件付き分布」は、データを作った分布の確率で順位を付けたもの
  - このデータで届く上限の目安になる
- 「参考 人気順」は、訓練の正例の出現頻度だけで順位を付けたもの

### 偽の負例の除外とバッチサイズ

c と d を、バッチサイズを変えて訓練した（種3つ）

| バッチサイズ | 変種 | recall@10 | recall@50 | 上位10件に占める人気上位1%の割合 |
|---:|---|---:|---:|---:|
| 256 | c | 0.591 ± 0.002 | 0.855 ± 0.002 | 0.278 ± 0.000 |
| 256 | d | 0.592 ± 0.001 | 0.854 ± 0.001 | 0.278 ± 0.000 |
| 1,024 | c | 0.593 ± 0.003 | 0.855 ± 0.000 | 0.276 ± 0.002 |
| 1,024 | d | 0.594 ± 0.002 | 0.854 ± 0.000 | 0.276 ± 0.002 |
| 4,096 | c | 0.592 ± 0.002 | 0.853 ± 0.001 | 0.277 ± 0.000 |
| 4,096 | d | 0.592 ± 0.001 | 0.853 ± 0.001 | 0.277 ± 0.001 |

### 負例の数と InfoNCE の下界

種0のモデルで、テスト20,000対の各行に、訓練の正例の出現頻度に比例して負例を `N - 1`件引いた
値は `log N - 損失`（nats）

| 候補数 N | log N | a | b | c | d |
|---:|---:|---:|---:|---:|---:|
| 2 | 0.693 | 0.680 | 0.678 | 0.668 | 0.665 |
| 8 | 2.079 | 1.995 | 1.987 | 1.937 | 1.925 |
| 32 | 3.466 | 3.165 | 3.135 | 2.983 | 2.947 |
| 128 | 4.852 | 4.049 | 3.974 | 3.670 | 3.599 |
| 512 | 6.238 | 4.506 | 4.371 | 3.901 | 3.796 |
| 2,048 | 7.625 | 4.616 | 4.456 | 3.891 | 3.766 |
| 8,192 | 9.011 | 4.630 | 4.470 | 3.882 | 3.752 |

データの相互情報量の真値は4.957

## 結果の読み方

- a は人気の商品を上位から外した
  - 上位10件に占める人気上位1%の割合は0.038で、真の条件付き分布の0.279の約7分の1だった
- 一様な負例（b）と logQ 補正（c）を足すと、recall@10 は0.163から0.593に上がり、人気の割合も真の分布並みの0.276に戻った
- 偽の負例の除外（d）は、正例が重なる行が60%のバッチ4,096でも、c と差が出なかった
- 下界は N=2では log N に近く、N を増やすと a でも4.63で止まり、真の相互情報量4.957に届かなかった
- 下界の大きい順（a > b > c > d）は検索の精度の順と逆で、損失の値は負例の扱いを選ぶ基準にならない

### 考えられる理由

- バッチ内の負例は正例の出現頻度に比例して入るので、a のスコアは `log P(次|基準) - log Q(次)` に近づき、人気の分が打ち消される
  - logQ 補正はロジットから log Q を引いて訓練するので、スコアそのものは `log P(次|基準)` に近づく
- InfoNCE の下界を最大にするスコアは `log P(次|基準) - log P(次)` のほうなので、検索に合う c と d ほど下界が小さくなる
- d で差が出なかったのは、重なった列が正例と同じ商品で同じスコアを持ち、除外しても勾配の向き（正例を上げ、ほかの商品を下げる）は変わらないためと考えるが、確かめていない
  - d が除くのは同じ商品だけで、同じクラスタの別の商品は負例のまま残る
- c と d の下界は N=512を過ぎるとわずかに下がった
  - スコアを固定したまま N を増やしても、下界が上がり続けるとは限らない
