# react_search

ReAct 形式のエージェント型の検索をローカルの LLM で動かし、1回の検索の RAG と比べる実験

確かめたいことは2つある

- どんな問いで検索を繰り返すと答えが良くなるか
- 停止文字列が無いと、LLM は実行していない検索の結果を作文するか

検索の対象は日本国憲法の第一条から第百三条まで（リポの `go/internal/enginecmp/kenpou.json` を読む）
モデルは `mlx-community/gemma-3-4b-it-4bit` を mlx-lm で動かす
有料の API は使わない

## 仕組み

### ツール

| 行動 | 中身 |
|---|---|
| `search[クエリ]` | 文字 bi-gram で分割した BM25（k1=1.2、b=0.75、自前の実装）で上位3件の条文を返す |
| `lookup[語]` | 直前の search で開いた3件の条文から、語を含む文を返す |
| `finish[回答]` | 回答して終わる |

比べるために部分一致の検索（`substring_search`）も用意した
クエリを空白と句読点で語に分け、含む語の数が多い条文から3件を返す
ReAct のループには使わず、検索だけの比較に使う

### ReAct のループ

モデルには次の形式で書かせる

```text
思考 1: 首相の指名についての条文を探す
行動 1: search[内閣総理大臣 指名]
観測 1: （ここはループがツールを実行して差し込む）
思考 2: ...
行動 2: finish[国会]
```

指示の後に、図書館の規則を題材にした自作の例を3つ置く（`prompts.py`）
例は、1回の検索で答える例、言い換えて検索し直してから lookup で確かめる例、2回の検索で列挙を集める例にした

1回の生成ごとに、ループは次のことをする

- 出力を停止文字列（`観測 n:` と、改行に続く `観測`）で切る
- 切った出力から最初の行動を取り出し、search と lookup ならツールを実行して `観測 n:` の後に結果を差し込む
- 行動を取り出せなければ形式崩れとして数え、「行動を解析できなかった」という観測を差し込んで次に進む
- finish なら終わる
- 反復の上限（2回か5回）に達しても finish しなければ強制終了し、回答は空にする

mlx-lm の `BatchGenerator` には「改行に続く `観測`」のトークン列を停止条件として渡し、生成を早めに打ち切る
停止文字列で正確に切るのは、ループの側で文字列に対して行う

### 比べる設定

| 設定 | 中身 |
|---|---|
| (参考) 検索なし | 問いだけを渡して答えさせる |
| (a) 1回の検索 | 問いをそのまま BM25 で検索し、上位3件を文書1〜3として並べ、問いを末尾に置いて答えさせる |
| (b) ReAct 上限2回 | 停止文字列あり、反復は2回まで |
| (c) ReAct 上限5回 | 停止文字列あり、反復は5回まで |
| (d) 停止文字列なし 上限5回 | 停止文字列を渡さない以外は (c) と同じ |

(d) のループは、停止文字列を知らない素朴な実装として次のように動く

- 生成した文章を切らずにそのまま記録に足す
- 文章のどこかに finish があれば、その回答で終わる（モデルが自分で書いた観測の後の finish でも終わる）
- finish が無ければ、最初の行動だけを実行して本物の観測を末尾に足す

モデルが自分で書いた `観測 k:` は、その直前の行動を本物の環境の写しで実行した結果と比べる
書いた観測に出てくる条文番号がすべて実際の結果にあり、かつ書いた観測の文字 bi-gram の半分以上が実際の結果に含まれるときだけ一致とみなす
それ以外を食い違いとして数える
条文番号を書かずに問いの語を写し、数字だけを変えた作文は一致とみなされるので、食い違いの数は少なめに出る基準になっている

### 問いの組

24問を自作した（`questions.py`）
種類ごとに6問ある

| 種類 | 例 | 正解の語 | 根拠の条文 |
|---|---|---|---|
| 1つの条文 | 参議院議員の任期は何年か | 六年 | 第四十六条 |
| 語のずれ | 首相を指名するのはどこか | 国会 | 第六十七条（条文は「内閣総理大臣」） |
| 列挙 | 国民の三つの義務を挙げよ | 教育 / 勤労 / 納税 | 第二十六条 / 第二十七条 / 第三十条 |
| 2段 | 予算をさきに提出しなければならない議院の議員の任期は何年か | 四年 | 第六十条で衆議院と分かり、第四十五条で四年と分かる |

正解の語には表記の揺れ（「四十日」と「40日」など）を並べ、どれかが回答に含まれれば当たりにする
根拠の条文にも別解を持たせた（憲法改正の公布は第七条と第九十六条のどちらにも書いてある）

### 指標

| 指標 | 定義 |
|---|---|
| 正答率 | 正解の語が回答に含まれる割合。列挙は正解の語の再現率で、問いごとの値を平均する |
| 根拠の再現率 | 根拠の条文のうち、検索で一度でも上位3件に入ったものの割合。lookup は新しい条文を開かないので数えない |
| 検索の回数 | 実際に実行した search の回数の平均。(d) でモデルが作文しただけの検索は数えない |
| 秒/問 | 生成の時間を、同じ束で生成した要求の数で割って問いごとに足した値 |
| 強制終了 | 反復の上限に達しても finish しなかった問いの数 |
| 形式崩れ | 行動を解析できなかった生成が1回でもあった問いの数（括弧内は生成の回数） |

検索なしと1回の検索の回答は、指示どおり出力の1行目だけを使う
ReAct の回答は finish の引数を使う

### 検索だけの比較（LLM なし）

根拠の再現率を、検索の方式とクエリの作り方で比べる
ReAct のクエリは (c) でモデルが実際に出したクエリで、同じクエリを部分一致の検索でも引き直した

| 種類 | 問い数 | BM25 問いそのまま | 部分一致 問いそのまま | BM25 ReAct のクエリ | 部分一致 ReAct のクエリ |
|---|---|---|---|---|---|
| 1つの条文 | 6 | 100% | 17% | 100% | 83% |
| 語のずれ | 6 | 83% | 0% | 33% | 50% |
| 列挙 | 6 | 62% | 0% | 62% | 58% |
| 2段 | 6 | 83% | 0% | 67% | 50% |
| 全体 | 24 | 82% | 4% | 65% | 60% |

### 読み方

4B のモデルは3つの例を見て形式を守り（形式崩れ0回）、停止文字列があれば本物の観測をもとに答えた
ただし検索を繰り返さず、1回の検索 (a) の57%に対して ReAct (c) は41%に下がった
下がった主な理由はクエリで、モデルは「首相」「閣僚 役割」のような短いクエリを作り、問いの中で条文に重なっていた語（「指名」「でなければならない」）を落とした
上限を2回から5回に上げて34%から41%に上がったのは、2回目に lookup で確かめて3回目に finish した問いが強制終了を免れた分で、4回目以降に進んだ問いは無かった
停止文字列が無いと、24問すべてで実行していない検索の結果を作文し、その作文を根拠に回答して、正答率は検索なしの20%より低い8%になった

### 問いの種類ごとに見えたこと

- 語のずれの問いで2回目の検索をしたのは3問で、どれも1回目が0件か無関係な条文だった後だった
  - 2回目も「内閣 構成」「憲法 役割」「公務員 給料」と問いの語の周りで検索し、条文の言葉（内閣総理大臣、国務大臣、歳費）に言い換えた問いは無かった
  - (a) は、問いに含まれる別の語が条文に重なって根拠が取れた（「首相を指名するのはどこか」は「指名」で第六十七条が取れた）
- 2段の問いで、1つ目の条文で分かった語を使って2つ目を検索した問いは0問だった
  - 「予算をさきに提出しなければならない議院の議員の任期」は、lookup で第六十条から衆議院と分かったのに、衆議院議員の任期を検索せずに答えた
  - 「皇室典範を議決する機関は国権の何か」は、開いている条文の中で lookup[国権] を探して見つからず、検索し直さずに答えた
- 列挙の問いで2回目の検索をした問いは0問だった
  - 根拠の条文が取れていても（「三分の二以上の多数による議決」は4件のうち3件が取れた）、回答は条件を言い直すだけで、項目を並べなかった
  - 列挙で足りないのは検索より、取れた条文から項目を拾って並べる読み取りの側だった
- 検索で答えが悪くなった問いもある
  - 「憲法が保障する自由を挙げよ」は検索なしで80%だったが、(a) では第十二条の「自由及び権利」を写して0%になった
- 部分一致の検索は、問いそのままでは4%しか根拠を取れないが、ReAct のクエリなら60%取れた
  - クエリを語に分けるエージェントの書き換えは、語で引く検索には効く
  - 文字 bi-gram の BM25 では、問いそのままのほうが根拠の再現率が高かった

### 限界

- 問いは24問で、1問の差で全体の正答率が約4ポイント、種類ごとの正答率が約17ポイント動く
- 採点は正解の語が回答に含まれるかだけを見るので、条文を長く写す回答ほど当たりやすい
- ReAct の例は3つで、検索が空振りしたら条文の言葉で言い換える例は1つだけにした
  - 例や指示を変えたときの結果は未確認
- モデルは 4B の量子化版1つだけで、大きいモデルで検索を繰り返すようになるかは未確認
