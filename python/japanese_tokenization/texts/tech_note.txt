# 検索 API の応答時間を下げる設計メモ

## 背景

商品検索 API の p95 レイテンシが 820ms あり、目標の 300ms を超えている。
アクセスログを 7 日分集計すると、上位 5% のクエリが全リクエストの 62% を占めていた。
同じクエリが短い間隔で繰り返し届くので、結果をキャッシュすれば検索エンジンへの問い合わせの多くを省ける。

## 方針

- Redis に、クエリ文字列と絞り込み条件をキーにして検索結果を保存する
- TTL は 10 分にし、在庫数が変わったときは該当商品を含むキーを削除する
- キャッシュに無いときだけ Elasticsearch に問い合わせる
- ヒット率、レイテンシ、エラー率を Grafana のダッシュボードで監視する

## リスク

キャッシュの削除が漏れると、売り切れた商品が検索結果に残る。
削除の失敗をメトリクスにし、1 時間に 3 回を超えたらアラートを出す。
ホットキーに負荷が集中するとシャードの CPU 使用率が上がるので、ロードテストで 2,000 rps まで確認してからリリースする。

## 決めること

1. TTL を一律にするか、カテゴリごとに変えるか
2. ユーザーごとに並び順が変わるクエリを、キャッシュの対象から外すか
3. ロールバックの手順を誰が用意するか
